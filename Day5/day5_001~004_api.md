### 0-2. 기본 규칙 및 제약사항
- **Base URL**: `/api/v1`
- **데이터 응답 형식**: JSON (`application/json`)
- **인증 방식**: HTTP Bearer Token (`Authorization: Bearer <access_token>`)
- **비기능 요구사항 (NFR-PTNT-001)**: 모든 API는 **최대 3초 이내** 처리 및 응답 수행

### 0-3. 권한(Role)별 접근 범위
- `STAFF` / `ADMIN`: 환자 및 진료기록 전체 CRUD 접근 허용 (사내 개발진, 의료 실무진, 연구진)
- `PENDING`: 접근 불가 (`403 Forbidden`)

### 0-4. 공통 에러 응답 구조
```json
{
  "detail": "에러 메시지 내용"
}
```

## 1. 환자 정보 관리 API 명세 (REQ-PTNT-001 ~ 004)

### 1-1. REQ-PTNT-001: 환자 정보 등록 API

#### 개요
- **기능**: 사내 의료진 역할을 가진 유저가 환자 관리 메뉴에서 모달을 통해 신규 환자 정보를 등록합니다.
- **HTTP Method**: `POST`
- **Endpoint**: `/api/v1/patients`
- **인증 필요 여부**: Y (`Bearer Token`)
- **권한**: `STAFF`, `ADMIN`

#### Request Body (`application/json`)
| Field | Type | Required | Description | Example / Constraint |
| :--- | :--- | :---: | :--- | :--- |
| `name` | string | Y | 환자 이름 | `"홍길동"` |
| `age` | integer | Y | 환자 나이 | `45` (0 이상) |
| `gender` | string | Y | 성별 Enum | `"M"` 또는 `"F"` |
| `phone_number` | string | Y | 연락처 (휴대폰 번호) | `"01012345678"` (하이픈 없이 입력) |

#### Response Body (`201 Created`)
```json
{
  "id": 1,
  "name": "홍길동",
  "age": 45,
  "gender": "M",
  "phone_number": "01012345678",
  "created_at": "2026-10-27T10:00:00Z",
  "updated_at": "2026-10-27T10:00:00Z"
}
```

#### Status Codes
- `201 Created`: 환자 정보 등록 성공
- `400 Bad Request`: 필수 항목 누락 또는 유효성 검증 실패 (잘못된 전화번호/성별 형상)
- `401 Unauthorized`: 토큰 미제공 또는 만료
- `403 Forbidden`: 권한 없음 (`PENDING` 계정)

## 2. 진료 기록 관리 API 명세 (Medical Record API)

### 2-1. 진료기록 등록 API

#### 개요
- **기능**: 특정 환자에 대한 차트 넘버, 증상 내용, 흉부 X-ray 이미지 파일(로컬 저장소 저장)을 포함한 진료기록을 등록합니다.
- **HTTP Method**: `POST`
- **Endpoint**: `/api/v1/patients/{patient_id}/records`
- **Content-Type**: `multipart/form-data`
- **인증 필요 여부**: Y (`Bearer Token`)
- **권한**: `STAFF`, `ADMIN`

#### Path Parameters
| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `patient_id` | integer | Y | 진료기록을 추가할 환자 ID |

#### Request Form-Data
| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `chart_number` | string | Y | 차트 넘버 |
| `symptoms` | string | Y | 진료된 증상 상세 |
| `xray_image` | file | Y | 흉부 X-Ray 이미지 파일 (JPEG/PNG) |

#### Response Body (`201 Created`)
```json
{
  "id": 101,
  "patient_id": 1,
  "chart_number": "C-20261027-01",
  "symptoms": "기침 및 발열 증상이 3일간 지속됨.",
  "xray_image_path": "/media/xrays/20261027_01_xray.png",
  "created_at": "2026-10-27T10:30:00Z"
}
```

### 3. 주요 변경 및 코드 반영 사항

1. **실제 데이터 모델 & Pydantic 스키마 매핑**
   - **`GenderEnum`**: `"male"`, `"female"` 값 매핑 반영.
   - **`PatientCreate` Validation**: `phone_number` 정규식 (`^\d{10,11}$`), 나이 범위 (`0 ~ 150`) 반영.
   - **`PatientUpdateRequest`**: `name`과 `phone_number`만 선택 수정 가능하도록 명시.
   - **`MedicalRecordListItem`**: Pydantic `@field_validator`로 구현된 `symptoms` 100자 줄임표 처리 로직 반영.

2. **엔드포인트 및 권한 로직 정밀 반영**
   - **`POST /api/v1/patients`**: `get_medical_user` 의존성을 통한 의료진 부서(`medical team`) 접근 제한 적용.
   - **`GET /api/v1/patients`**: `min_age` > `max_age` 예외 처리 조건 반영.
   - **`DELETE /api/v1/patients/{patient_id}`**: DB Cascading 연쇄 삭제 외에도 `media/` 로직을 통한 로컬 X-ray 및 AI 히트맵 파일 삭제 프로세스 추가.
   - **`GET /api/v1/records/{record_id}`**: 최신 X-ray 이미지 1건을 개별 쿼리로 안전하게 조회하는 비동기 패턴 반영.
